# Printer Password Recovery Prototype — private archive

> Public experimental source: see [PUBLICATION.md](PUBLICATION.md) for actual checks, known defects, restored modules and operational limits. Earlier audit decisions are historical.

Экспериментальный Playwright-прототип для проверки поведения login-формы устройства под нагрузкой вариантов пароля.

## Решение по аудиту

Этот репозиторий не нужно публиковать и не нужно использовать в резюме.

Причины:

- основной сценарий — password brute-force automation;
- даже при легитимном использовании на собственном устройстве проект выглядит как offensive tooling;
- публичная демонстрация не усиливает профиль Python/React/business automation разработчика;
- возможны юридические и репутационные риски, если код будет использован не на собственном оборудовании.

## Что найдено

- В проверенном текущем коде используется placeholder `printer.local`, а не реальный адрес устройства.
- `.gitignore` закрывает `.env`, ключи, базы, CSV/XLS/XLSX и временные артефакты.
- Перед удалением/архивацией всё равно нужен full-history secret scan, потому что текущая ветка не доказывает чистоту истории.

## Рекомендация

- Оставить private только как личный исследовательский архив или удалить.
- Не закреплять, не делать public, не включать в портфолио.
- Если нужен безопасный публичный вариант, переписать идею как defensive rate-limit/login-form testing demo без перебора реальных паролей и без привязки к устройствам.

## Usage boundary

Использовать подобные инструменты допустимо только на собственных устройствах или при наличии явного письменного разрешения владельца системы.
